エンジニアの職務経歴書の書き方——採用担当者に「会いたい」と思わせる5つのポイント

転職エージェントに職務経歴書を送っても1週間音沙汰なし——これはよくある話です。採用担当者が「この人に会いたい」と思う職務経歴書と、そうでないものの差は何か。この記事ではエンジニア特有の失敗パターンと、実績を正しく伝えるための具体的な書き方を解説します。

職務経歴書で評価が分かれる理由

支援の現場でよく見るパターンがあります。同じスキルを持つ2人のエンジニアが、書き方の違いだけで書類選考通過率が大きく変わるケースです。

1人目：「Javaを使った業務システムの開発に携わりました」
2人目：「決済処理システムのバックエンドを担当し、月間3万件の取引を処理する基盤の設計・実装を行いました。AWSのECSを活用したコンテナ化でデプロイ時間を40%短縮」

採用担当者が見たいのは「何をやったか」ではなく「どんな成果を出したか」です。スキルシートは技術のリストではなく、あなたが入社後にどれだけ貢献できるかを伝える書類です。書き方だけで内定率が変わります。

よくある失敗パターン5つ

職務経歴書でよくある失敗をまとめます。自分の書類に当てはまるものがないか確認してみてください。

  • 技術スタックの羅列：「Java / Python / AWS / Docker / Git」と並べるだけでは、何が得意かが伝わりません。技術は「どう使ったか」の文脈で書くことが重要です。
  • 担当業務が受け身の表現：「〜に携わりました」「〜を担当しました」だけでは弱い。「〜を設計・実装しました」「〜の課題を解決しました」と能動的な表現に変えましょう。
  • 数字がない：「処理速度を改善した」より「処理時間を3秒から0.8秒に短縮した」の方が伝わります。チーム規模、処理件数、改善率など、数字が書けるところには必ず書く。
  • プロジェクトの説明が長すぎる：背景説明に文字数を使いすぎて、自分の貢献が伝わりにくくなるケースです。採用担当者が知りたいのはプロジェクトの詳細ではなく、あなたがそこで何をしたかです。
  • SES特有：客先名が書けないからと記載が薄くなる：客先名を伏せても、業界・規模・使用技術・担当フェーズは書けます。情報を出せないからといって空白にするのは機会損失です。

採用担当者が見ているポイント

採用担当者は職務経歴書を読むとき、主に3つのことを確認しています。

  • 任せられるか：経験年数・スキルセットではなく、「このポジションで即戦力になれそうか」を見ています。求人票の必須スキルと照らし合わせながら、関連する経験を優先的に書きましょう。
  • 成果を出してきたか：同じ経験年数でも、ただ関わったのか、主体的に成果を出してきたのかで評価が変わります。課題→行動→結果の3段構成で書くと伝わりやすくなります。
  • 一緒に働けそうか：文章の読みやすさ、情報の整理のされ方、誤字脱字の有無からも印象が形成されます。コミュニケーション能力や仕事の丁寧さも間接的に伝わります。

「採用担当者は大量の書類を見ている」という事実を意識することが大切です。10〜20秒でスキャンされ、「もっと読みたい」と思ってもらえるかどうか。最初の1〜2行が勝負です。

成果の書き方——SES・SIerエンジニア向け

SES・SIerのエンジニアがよく口にするのが「客先常駐なので書ける内容が限られる」という悩みです。ただし、客先名や詳細な業務内容を伏せても、書けることは十分あります。

書き方の基本フレームは「課題→行動→成果」です。

  • 課題：プロジェクトやチームが抱えていた問題。例：「既存システムのデプロイに毎回30分以上かかっており、リリース頻度が月1回に制限されていた」
  • 行動：自分が何をしたか。例：「CI/CDパイプラインを設計・構築し、Dockerコンテナ化と合わせてデプロイフローを自動化した」
  • 成果：結果として何が変わったか（数字があればなお良い）。例：「デプロイ時間を5分以内に短縮し、リリース頻度を週2〜3回に改善。バグ修正のリードタイムも半減した」

客先名を書けなくても、業界（金融系・EC系・製造業など）、システム規模（ユーザー数、処理件数、チーム人数）、自分が担当したフェーズ（要件定義・設計・実装・テスト・運用）は書けます。これらを入れるだけで、書類の情報密度が大きく変わります。

書き直し前のチェックリスト

職務経歴書を書き直す前に、以下の項目を確認してください。

  • 最新のプロジェクト経験が上に来ているか（逆年代順になっているか）
  • 技術スタックが「使った」だけでなく「どう使ったか」で書かれているか
  • 数字を使える箇所（処理件数・改善率・チーム規模・期間）に数字が入っているか
  • 「〜に携わりました」ではなく「〜を設計・実装しました」など能動的な表現になっているか
  • 担当フェーズ（要件定義・設計・実装・テスト・運用・改善）のうちどこまで関与したか明示されているか
  • A4・1〜2枚に収まっているか（3枚以上は読まれにくくなる）
  • 誤字脱字・フォーマットの乱れがないか

これらのポイントをすべて満たした上で、「この人に会いたい」と思ってもらえる書類になっているかを確認してみてください。迷ったら転職のプロに一度見てもらうのが最短の改善方法です。

よくある質問（FAQ）

Q：職務経歴書は何枚が適切ですか？

A4・1〜2枚が理想です。経験年数が長い場合でも、直近3〜5年を厚く書き、それ以前は簡潔にまとめることが基本です。3枚以上になる場合は情報を絞る判断が必要です。

Q：客先常駐の経験だけでも転職できますか？

できます。業界・スキルセット・担当フェーズを整理し、成果を「課題→行動→成果」の形式で書けば、客先常駐経験は十分な武器になります。大切なのは、何をしたかではなく、何を変えたかです。

Q：ブランク期間がある場合、どう書けばいいですか？

ブランクの理由を正直に、かつ簡潔に書くことが基本です。資格取得・勉強・体調管理など、前向きな行動があれば記載しましょう。隠そうとするより、説明できる状態にしておく方が面接での印象が良くなります。

Q：エージェントに書類を見てもらうべきですか？

一度は見てもらうことをおすすめします。自分では気づかない「業界の常識」や「採用担当者の目線」をフィードバックしてもらえます。ただし最終的な内容は自分で責任を持って確認しましょう。

まとめ

職務経歴書で評価が変わるのは、スキルの差ではなく「伝え方」の差です。同じ経験でも、書き方によって採用担当者の印象は大きく変わります。

まずは今の職務経歴書を開いて、「技術の羅列になっていないか」「数字が入っているか」を確認することから始めてみてください。書き直す作業自体が、自分の市場価値を整理する機会にもなります。
