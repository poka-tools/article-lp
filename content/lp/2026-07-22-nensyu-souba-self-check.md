# 今の年収、市場相場より高い？低い？——エンジニアが3分でできる"年収が適正かのセルフチェック"手順

あなたの年収を止めているのは、スキル不足ではない。相場を知らないことだ。

多くのエンジニアが「もっと評価されてもいいはずだ」とうっすら感じながら、その感覚を数字に変換できないまま何年も過ごしている。感覚のままだと動けない。だが、相場という「基準線」を一本引くだけで、自分の年収が高いのか低いのか、3分で判定できる。

この記事は「転職しろ」とは言わない。やることはたった1つ、**まず自分の相場を調べるだけ**。それだけで、次の一手が驚くほど明確になる。

---

## まず相場の"基準線"を先に置く——アンカーがないと判断できない

自分の年収が適正かを判断するには、比較対象がいる。感覚ではなく数字だ。まず、この基準線を頭に入れてほしい。

| 区分 | 年収の目安 |
|------|-----------|
| SES平均 | **約408万円** |
| IT業界全体の平均 | **約537万円** |
| Web系・自社開発の中央値 | **約600万円前後** |

SES平均とIT業界全体では、すでに約129万円の差がある。これは能力差ではない。「どの土俵に立っているか」の差だ。

さらに、経験年数と職種でレンジは動く。ざっくりした目安はこうだ。

| 経験年数 | 相場レンジ（目安） |
|---------|------------------|
| 1〜3年 | 350〜480万円 |
| 4〜6年 | 450〜600万円 |
| 7〜9年 | 550〜720万円 |

| 職種 | 相場の傾向 |
|------|-----------|
| バックエンド開発 | 中〜高（設計・DB経験で上振れ） |
| インフラ・運用 | 中（クラウド設計まで担うと上振れ） |
| フロントエンド | 中〜高（モダンフレームワーク経験で上振れ） |
| 監視・保守・ヘルプデスク | 低〜中（開発経験の言語化で化ける） |

この表を見て、すでに「自分は低いかもしれない」と感じた人がいるはずだ。その違和感こそ、セルフチェックの出発点になる。

---

## 3分でできる年収セルフチェック——7つの質問に答えるだけ

ここからが本題だ。紙でもスマホのメモでもいい。次の7項目に「はい／いいえ」で答えていく。所要時間は3分。転職活動ではない。ただの現状把握だ。

**セルフチェック7項目**

- [ ] ① 自分の職種・経験年数の「相場レンジ」を、上の表で確認した
- [ ] ② 今の年収は、そのレンジの「中央値」より上にある
- [ ] ③ 直近2年で、年収が20万円以上（もしくは1回でも明確に）上がった
- [ ] ④ 自分が担当した業務を「使った技術・規模・役割」で3行以上説明できる
- [ ] ⑤ 同じ経験年数の他社エンジニアの年収を、直近半年で1件でも見た
- [ ] ⑥ 今の会社の給与テーブルで、この先3年の上限が見えている（頭打ちを感じていない）
- [ ] ⑦ 「今の年収は相場より高い」と数字の根拠を持って言える

**判定基準はシンプルだ。**

- 「はい」が **5〜7個**：あなたの年収は相場と釣り合っている可能性が高い。今は相場を定点観測しておけば十分。
- 「はい」が **3〜4個**：グレーゾーン。相場を「調べていないだけ」で取りこぼしが起きているサインだ。
- 「はい」が **0〜2個**：相場より低い可能性が高い。ただし悲観する必要はない。**低いのは能力ではなく、相場を知らずに据え置かれてきただけ**だからだ。

特に注目してほしいのは⑤と⑦だ。この2つに「いいえ」がつく人が非常に多い。裏を返せば、多くのエンジニアは「自分の年収が高いか低いか」を、一度も数字で確かめないまま働いている。判断材料を持っていないのだから、動けなくて当然なのだ。

もう少し補足しておく。②の「中央値より上か」は、平均ではなく中央値で見るのがコツだ。平均は一部の高年収者に引き上げられて実態より高く出やすい。中央値は「ちょうど真ん中の人」の水準なので、自分の立ち位置を正確に測れる。

④の「3行で説明できるか」は、地味だが決定的な項目だ。相場が同じでも、経験を言語化できる人とできない人では提示額が変わる。「監視を担当していた」ではなく「◯台規模のサーバーをどんなツールで監視し、障害時にどう一次対応したか」まで言えるか。これができるだけで、同じ経歴が別物に見える。逆にここが弱いと、実力があっても相場の下限で見積もられてしまう。

⑥の「頭打ちを感じているか」も見逃せない。今の会社の給与テーブルで数年先の上限が見えているなら、その上限があなたの相場ではない。会社ごとの天井と、市場全体の相場は別物だ。社内の天井を自分の限界だと思い込んでいないか、ここで一度切り離して考えてほしい。

チェックが終わったら、次のステップはたった1つ。**自分の市場価値を1回だけ調べる**。応募でも面談でもない。「今の自分に、市場はいくら出すのか」という相場の実数を見るだけだ。この1アクションで、7項目の「いいえ」の多くが埋まる。そして重要なのは、調べた結果がどうであれ、この時点では何も決めなくていいということ。事実を1つ手に入れるだけで、この記事の目的は達成される。

## 相場を知って動いた人たちの事例——最初の一歩は"調べただけ"

「調べるだけ」で本当に変わるのか。実際に動いた人の事例を2件、数字入りで紹介する。

**事例1：SES・経験5年・年収440万円だったAさん**
Aさんはセルフチェックで「はい」が2個。⑤も⑦も「いいえ」だった。半信半疑で市場価値を調べたところ、担当していたクラウド環境の運用経験が想定より高く評価され、提示レンジは540〜580万円。「自分の経験がこの金額で評価されるのか」と初めて数字で実感し、そこから伝え方を整えて最終的に年収は120万円上がった。彼が最初にやったのは、応募ではなく「調べること」だった。

**事例2：バックエンド・経験8年・年収520万円だったBさん**
市場相場（7〜9年で550〜720万円）と比べ、自分が下限より低いことにチェックで気づいたBさん。設計とDBチューニングの経験を3行で言語化しただけで、相場の中央値を超える提示を複数受けた。「スキルは足りていた。足りなかったのは、相場を知ることと、伝え方だった」というのが本人の言葉だ。

こうした変化は特別な才能の話ではない。厚生労働省の一般職業紹介状況でも、IT・情報処理技術者の有効求人倍率は全職種平均を上回る水準で推移しており、エンジニアは今も「探されている側」だ。つまり、相場を調べて自分の位置を知るだけで、選択肢は思っているより広い。

## 「相場を知らないまま据え置く」ことの本当のコスト

ここで一度、動かないことのコストを直視してほしい。

セルフチェックで「はい」が0〜2個だった人が、相場より年間80万円低い水準に据え置かれていたとする。これを3年放置すれば、単純計算で **累積240万円** の取りこぼしだ。しかも年収は昇給の起点になるため、低いスタートは翌年以降の差をさらに広げていく。

見落としがちなのは、この損失が「何もしていないのに毎年発生し続ける」という点だ。相場を調べるコストはゼロに近い。一方で、調べないことのコストは毎年静かに積み上がっていく。

「面倒だから」「今は安定しているから」で先送りにしている間も、時計は動いている。だからこそ、大きな決断は今しなくていい。**まず相場を1回調べる。それだけ**でいい。

もう一つ、頭の片隅に置いてほしい変化がある。AIの普及で、エンジニアの評価は静かに二極化し始めている。AIを前提に設計・実装・運用を組み立てられる人材の相場は上振れし、そうでない領域は横ばい傾向だ。相場そのものが動いている今は、自分の位置を測り直す価値がいつもより高い時期だといえる。慌てる必要はない。ただ、「一度も測っていない」状態のままでいるのは、いちばんもったいない。

## まとめ——今日やることは「調べるだけ」の1つに絞る

長々と読んでもらったが、この記事で伝えたいことは、突き詰めればシンプルだ。

- 年収が適正かは、感覚ではなく**相場という基準線**と比べて初めて判断できる
- 3分のセルフチェック7項目で、自分が「高い側」か「低い側」かはすぐ分かる
- 年収を止めているのは、多くの場合スキルではなく「相場を知らないこと」だ
- 事例が示すのは、最初の一歩は転職ではなく「調べただけ」だという事実

やることを増やすと人は動けなくなる。あれもこれもと準備を並べた瞬間、「今は忙しいから」と先送りが始まる。だから今日の宿題は1つだけにする。**自分の市場価値を1回だけ調べる**こと。応募も、面談も、退職の決断も、その後でいい。むしろ、その1つ以外は今日やらなくていいと決めてしまったほうが、かえって手が動く。

セルフチェックで「いいえ」が多かった人ほど、調べたときの発見は大きい。低いのは、あなたの能力のせいではない。相場を知らないまま据え置かれてきただけだ。その1点を、今日ひっくり返してほしい。

基準線はもう、この記事で手に入れた。あとは、自分の実数を確かめるだけだ。3分あればできる。今日のうちに、その1つだけ済ませてしまおう。
