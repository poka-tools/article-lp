1. Claude Codeってそもそも何？チャットと何が違うの？
──────────────────────────────

Claude.aiのチャット画面でAnthropicのAIを使ったことがある方は多いと思います。
でも「Claude Code」はちょっと違います。

Claude Codeは、ターミナル（コマンドライン）から起動するAIアシスタントです。
チャット画面と違うのは、「ファイルを直接読み書きできる」こと。
指示すれば、プロジェクトのコードを開いて・書き換えて・保存してくれます。

```
# インストール
npm install -g @anthropic-ai/claude-code

# 起動
claude
```

これだけで、ターミナル上でClaudeと会話しながら開発ができるようになります。
最初は「AIと会話してるだけ」に感じるかもしれません。
でも使い込んでいくと、スラッシュコマンド・Hooks・MCPというしくみが
いかにすごいかがわかってきます。


2. まず覚えたいスラッシュコマンド一覧
──────────────────────────────

スラッシュコマンドは「/」から始まるショートカット命令です。
チャットで長文を打たなくても、コマンド一発でよく使う操作が完結します。

【基本コマンド】

| コマンド        | 何をするか                                      |
|----------------|------------------------------------------------|
| /help          | 使えるコマンド一覧を表示する                     |
| /init          | CLAUDE.mdを自動生成（プロジェクト把握の初期設定） |
| /clear         | 会話履歴をリセットする                           |
| /compact       | 会話を圧縮して長いコンテキストを継続できるようにする|
| /memory        | メモリ（記憶）の内容を確認・管理する              |
| /config        | テーマ・モデルなどの設定を変更する                |
| /review        | 変更したコードのレビューを依頼する                |
| /cost          | このセッションで使ったAPIコストを確認する          |
| /status        | ステータスバーの設定を変更する                   |

【便利な使い方のポイント】

「/」を打つと候補が出てくるので、最初は全部覚えなくて大丈夫です。
まず `/init` と `/review` だけ使えるようにしておくと、
プロジェクト初期設定とコードレビューが一気に楽になります。


3. CLAUDE.mdとは？プロジェクトの「取説」を自動生成する /init
──────────────────────────────

Claude Codeを使い始めるとき、最初にやるべきことがあります。
それが `/init` コマンドです。

```
/init
```

このコマンドを実行すると、Claudeがプロジェクトのコードを読んで
`CLAUDE.md` というファイルを自動生成してくれます。

CLAUDE.mdには以下のような情報が書かれます：
- プロジェクトの概要・目的
- 使っている技術スタック
- ディレクトリ構成
- 命名規則・コーディングスタイル
- よく使うコマンド

これを作っておくと、次回以降Claudeがプロジェクトを「知った状態」で動いてくれます。
毎回「このプロジェクトはReactで、TypeScriptを使って…」と説明しなくて済むわけです。

また、CLAUDE.mdは自分でカスタマイズできます。
「〇〇は必ずセキュリティチェックして」「コメントは日本語で書いて」など
ルールを書いておけば、Claudeが毎回それを守って動いてくれます。


4. Hooksで繰り返し作業をゼロにする方法
──────────────────────────────

「毎回同じことを頼むのが地味に面倒」と感じたことはありませんか？

Claude CodeのHooksは、特定のタイミングで自動的にコマンドを実行する仕組みです。
設定ファイル（settings.json）に書いておくだけで、
毎回Claudeに頼まなくても自動で動いてくれます。

【Hooksが使える主なタイミング】

| タイミング           | 例                                              |
|---------------------|-------------------------------------------------|
| PostToolUse         | ツール使用後（ファイル編集後など）に実行          |
| Stop                | Claudeの応答が終わったときに実行                 |
| PreToolUse          | ツール使用前に実行（確認・ブロックなど）           |
| Notification        | 通知が来たときに実行                             |

【設定の例】

```json
// .claude/settings.json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit",
        "hooks": [
          {
            "type": "command",
            "command": "npx prettier --write ."
          }
        ]
      }
    ]
  }
}
```

この設定を書くと、Claudeがファイルを編集するたびに
自動でPrettierが走ってコードが整形されます。
毎回「フォーマットして」と頼む必要がなくなるわけです。

他にも「コミット前にESLintを走らせる」「処理完了後に通知音を鳴らす」など
工夫次第でいろんな自動化ができます。


5. MCPサーバーでClaude Codeを外部ツールと繋げる
──────────────────────────────

「MCP」はModel Context Protocolの略で、
Claude Codeに外部ツール・サービスを接続する仕組みです。

正直、最初は「難しそう」と思っていました。
でも実際に試してみると、設定は数行で済むし、
できることが一気に広がります。

【MCPで繋げられる主なツール（一例）】

- GitHub：PRの内容取得・レビュー・issue作成
- Notion：ドキュメントの読み書き
- Slack：メッセージの送受信・検索
- Google Drive：ファイルの取得・編集
- ブラウザ操作（Puppeteerなど）

【設定の例（GitHubを繋ぐ場合）】

```json
// .claude/settings.json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "your_token_here"
      }
    }
  }
}
```

この設定を書いておくと、
「このPRのコードレビューして」と言うだけでClaudeがGitHubから情報を取ってきて
レビューを返してくれます。

Claudeが「情報を取りに行く」ようになる感覚は、
使ってみると思った以上に快適です。


6. 実際にどう使ってる？ リアルな1日の活用フロー
──────────────────────────────

頭でっかちになっても仕方ないので、実際の使い方を書きます。

【朝：プロジェクト開始時】
```
cd my-project
claude
/init   # プロジェクト初期把握（初回のみ）
```

【開発中：コード生成・修正】
```
# 普通に会話で依頼する
「UserテーブルにemailカラムをNOT NULLで追加するマイグレーション書いて」

# Claudeがファイルを直接編集してくれる
```

【コード確認：レビュー依頼】
```
/review
# 変更差分をClaudeが確認して、問題点・改善点をコメントしてくれる
```

【繰り返し作業：Hooksで自動化】
- ファイル保存のたびにPrettierが自動で走る（settings.json設定済み）
- 余計な手作業ゼロ

【外部連携：MCP経由】
```
「GitHubのPR #42のレビューコメントに返信して」
# MCPでGitHubに繋いでいれば、これだけで完結
```

毎日この流れで使っていると、
「頼む・確認する・自動化する」のサイクルが自然にできあがってきます。


7. よくある疑問（FAQ）
──────────────────────────────

Q. Claude Codeは有料ですか？
A. Anthropic APIのトークン消費になります。API使用量に応じた料金が発生します。
   claude.ai Proプランでも利用可能です。

Q. Windows・Macどちらでも使えますか？
A. どちらでも使えます。WSL（Windows Subsystem for Linux）環境でも動作します。

Q. AIにコードを見せることのセキュリティリスクは？
A. APIを通じてAnthropicのサーバーに送信されます。
   機密情報・APIキーなどはCLAUDE.mdや .env で管理し、
   直接コードに書かないようにすることを推奨します。

Q. スラッシュコマンドは自作できますか？
A. カスタムスラッシュコマンドの機能があります。
   よく使う指示をコマンド化して呼び出すことができます。

Q. Hooksの設定を間違えるとどうなりますか？
A. エラーが起きてもClaude Code本体の動作は止まりません。
   hook実行エラーはログに出るので確認して修正できます。


8. まとめ
──────────────────────────────

Claude Codeは「チャットするAI」ではなく、「一緒に開発するパートナー」です。

- **スラッシュコマンド**：チャット不要でよく使う操作を一発実行
- **CLAUDE.md**：プロジェクトのルールと構造をClaudeに覚えさせる
- **Hooks**：繰り返し作業を自動化して手作業をゼロに近づける
- **MCP**：外部ツールと繋いでClaudeの行動範囲を広げる

最初は「コード書いてもらうだけ」で十分です。
慣れてきたらHooksやMCPを足していくだけで、
開発効率は段階的に上がっていきます。

エンジニアとしての市場価値を上げるうえで、
「AIを使いこなせる」スキルは今後ますます重要になります。
まずは `claude` コマンドを起動してみるところから始めてみてください。
