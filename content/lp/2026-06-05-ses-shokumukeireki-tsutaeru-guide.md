# SESエンジニアの職務経歴書、ここを変えれば採用担当者の評価が変わる——常駐・下流工程でも市場価値が伝わる書き方の具体手順

SES歴3年以上のエンジニアが転職活動で落ち続ける原因の8割は、スキル不足ではなく「職務経歴書の書き方」にある。

現場で積み上げてきた経験を正しく言語化できれば、SES出身であることはハンデではなくむしろ武器になる。問題は「何をどう書けば評価されるか」の手順を誰も教えてくれないことだ。

この記事では、採用担当者が実際に何を見ているかを前提に、SESエンジニアが今日から職務経歴書を書き直すための具体手順を解説する。

## SES・ITエンジニア・事業会社——年収の実態比較

まず現実の数字を見てほしい。

| 区分 | 平均年収（目安） |
|------|----------------|
| SESエンジニア（〜5年） | 約408万円 |
| ITエンジニア全体平均 | 約537万円 |
| 事業会社（内製化推進企業） | 約650万円〜 |

この差は「スキルの差」ではない。同じ技術スタックを持っていても、所属形態と職務経歴書の書き方によって、採用担当者が「どこまで任せられるか」を判断する材料が変わってくる。

年収差は年間で129万円。3年間で387万円。この数字を意識した上で、次のセクションを読んでほしい。

SES出身者の多くは「自分の経歴では事業会社は無理だろう」という先入観を持っている。しかし支援してきた方々のケースを見ると、スキルセットそのものは十分に市場要件を満たしているケースが大半だ。差がつくのは「伝え方」だけである。

## SES職務経歴書が「読まれにくい」本当の理由

採用担当者は1件の職務経歴書を平均30秒以内でスクリーニングすると言われている。SES出身者の書類が弾かれやすい構造的な理由は3つある。

**理由1：プロジェクト羅列になっている**

SESの仕事の性質上、短期〜中期の常駐案件を複数経験することが多い。それをそのまま時系列で並べると「転々としているように見える」「何が得意かわからない」と判断される。採用担当者が見たいのは「この人は何ができるのか」であり、「どこに何年いたか」ではない。

**理由2：「担当しました」止まりの記述**

「Javaを使った基幹システムの開発を担当」という記述は、採用担当者にとってほぼ情報量ゼロに等しい。規模・役割・成果・工夫した点が一切見えないからだ。これはSESに限らないが、常駐形態では自分の貢献範囲を曖昧にする習慣がつきやすい。

**理由3：上流工程への不関与を「弱点」として隠している**

「要件定義・設計は上流がやっていたので書けない」という思い込みで、実装・テスト・保守フェーズの記述を薄くする傾向がある。しかし採用担当者の多くは、「実装フェーズの深さ」を重視している企業が相当数ある。特にプロダクト開発系の企業では、「コードを書ける人」の実装経験を高く評価する。

## 採用担当者は何を見ているか——実際のスクリーニング基準

「書類選考を通過する職務経歴書」と「落ちる職務経歴書」の差を、採用担当者視点で整理すると以下になる。

**採用担当者が見ている4つのポイント**

1. **技術スタックの具体性**：「Java」ではなく「Java 17 / Spring Boot 3.x / PostgreSQL 15」レベルの記述があるか
2. **規模感の提示**：チーム規模・システム規模・期間が数字で書かれているか（「5名チームで12ヶ月」「日次100万件処理のバッチ開発」等）
3. **役割の明確化**：メンバーとして作業したのか、一部のサブリード的役割を担ったのか
4. **問題解決の痕跡**：「課題 → 自分の行動 → 結果」の構造で書かれているか

**実例1：SES3年・26歳・Web系バックエンドエンジニア**

変更前の記述：「ECサイトのAPI開発を担当（Java/Spring Boot）」

変更後の記述：「日次注文処理100万件規模のECプラットフォームにおいて、商品検索APIのレスポンス改善を担当。N+1問題を特定しクエリ最適化を実施した結果、平均レスポンスタイムを800msから120msに短縮（85%改善）。5名チームのメンバーとして12ヶ月参画。」

この変更だけで、書類通過率が大きく変わった事例だ。内容は同じ経験でも、「何をしたか」「どのくらいのスケールか」「どんな成果があったか」が見えるだけで、採用担当者の評価軸が変わる。

## 今日から直せる——SES職務経歴書の書き方手順

以下の5ステップを順番に実施するだけで、職務経歴書の情報密度は大きく変わる。転職活動を今すぐ始めなくていい。まず「棚卸し」だけやってみればいい。

**Step 1：関わったプロジェクトを全部書き出す（棚卸しシート）**

箇条書きでいい。案件名・期間・技術スタック・チーム規模・自分の担当フェーズ（設計/実装/テスト/保守等）を5分で書き出す。この段階では見栄えを気にしない。

**Step 2：各プロジェクトで「自分が一番苦労したこと」を1行書く**

「レガシーコードの読解」「テスト工数の見積もりミスをリカバリした」「常駐先のコードレビュー文化に適応した」——何でもいい。採用担当者が見たいのはこの「課題認識と行動」の部分だ。

**Step 3：技術スタックをバージョン付きで整理する**

「Java」ではなく「Java 11 / 17」、「AWS」ではなく「EC2 / RDS / Lambda / CloudWatch」のように、使ったサービス・バージョンを具体化する。これだけで「ちゃんとやってきた人」という印象が変わる。

**Step 4：数字を入れられる箇所を探す**

チーム規模・システム規模・改善結果・参画期間・担当したテストケース数——どんな小さな数字でも、数値化できるものはすべて入れる。「約〇〇件」「〇名チーム」で十分。

**Step 5：プロジェクト羅列をスキル軸で再編集する**

時系列ではなく「Webアプリ開発」「バッチ処理」「インフラ構築」などスキル軸でグループ化することで、「何ができる人か」が一目でわかる構成になる。特に複数言語・複数業種を経験している場合はこの再編集が効果的だ。

## 「SES5年以上でも遅くない」——長いキャリアを武器にする逆転の書き方

「SESが長くなってしまった。今さら職歴を活かせる転職なんて無理かも」——この思い込みは、支援してきた方の中でも特に31〜36歳層に多い。

しかし事実は逆だ。SES経験5年以上の人材が持っている強みを、採用担当者が正確に把握するケースはまだまだ少ない。つまり、「伝え方さえ変えれば」市場評価は跳ね上がる余地がある。

**SES5年以上の人材が持つ「隠れた強み」**

- 複数業種（金融・流通・製造等）のシステムに触れた「業種横断の視野」
- 常駐先ごとに異なる開発文化・コミュニケーション様式に適応してきた「環境適応力」
- 多様なコードベースを短期間で読み解いてきた「キャッチアップ速度」
- 常駐先の社員と協力してきた「クライアントとの協業経験」

これらは事業会社側から見ると、即戦力として評価されやすい要素だ。

**実例2：SES8年・34歳・インフラエンジニア**

「8年間SES。AWSの設計・構築・運用を複数案件で担当。ほぼすべての案件でチームメンバーとして参画し、上流工程の経験なし」という職歴を持つ方が、職務経歴書のリライトだけで事業会社のシニアインフラエンジニアポジションへ転職。年収は520万から670万円に上昇した。

変更のポイントは「担当した運用設計の具体内容（監視アラート閾値設計・コスト最適化施策）」と「複数案件を通じて標準化してきたIaC（Terraform）の実績」を、プロジェクト羅列から切り出して「スキル実績セクション」として独立させたことだった。

## 転職しない場合の3年後シミュレーション——機会損失の実態

「今は忙しい」「もう少し経験を積んでから」「転職は怖い」——このまま3年間動かなかった場合、何が起きるか。

**年収差の累積計算**

現在のSES平均年収408万円と、転職後の事業会社平均650万円の差は242万円/年。
仮に転職後の年収が600万円だったとしても、差は192万円/年。3年間で576万円の累積差が生まれる。

この576万円は「稼ぎ損ない」ではなく「払い続けたコスト」と見るべき数字だ。

さらに物価上昇が続いている現在、年収が変わらないことは実質的な減給を意味する。総務省統計では2023〜2026年の4年間、消費者物価指数は累積で8%以上上昇している。年収400万円の人間が4年間年収を変えなければ、実質的な購買力は約33万円分減少している計算になる。

「今動かないことの安全性」は幻想だ。動かないことにも、確実なコストがかかっている。

## AI採用選別時代——今動き始める人が有利な理由

採用市場の構造が2025年以降、静かに変化している。

AI技術の普及により、採用担当者が候補者を評価するスピードと精度が上がっている。書類選考にAIスクリーニングを導入している企業は急増しており、「なんとなく読める職務経歴書」が通過できる時代は終わりに近づいている。

一方で、AIスクリーニングを通過した候補者に対して、人間の採用担当者は「この人を選ぶ積極的な理由」を探すようになっている。つまり、「落とされない書類」から「選ばれる書類」への転換が必要な時代に入っている。

SESエンジニアにとってのチャンスは今だ。

内製化を進める事業会社が増え、実装経験の豊富なエンジニアへの需要は高い。しかし採用は「誰でも採る」から「誰を選ぶか」への厳選型に移行している。この状況で有利なのは、「早めに動いて、伝える力を磨いた人」だ。

「まず職歴を棚卸しするだけでいい」——Step 1からの5ステップを今日やってみることが、3年後の576万円の差を決める起点になる。

## まとめ——SES経験は「正しく伝えれば」市場価値になる

この記事で伝えてきたことを整理する。

**SES職務経歴書の問題の本質**
- スキル不足ではなく「書き方の問題」がほとんど
- プロジェクト羅列・「担当しました」止まり・上流工程への誤った引け目が主な原因

**採用担当者が見ている4つのポイント**
- 技術スタックの具体性（バージョン・ツール名まで）
- 規模感の数字（チーム人数・システム規模・期間）
- 役割の明確化（メンバー/サブリード等）
- 課題 → 行動 → 結果の構造

**今日からできる5ステップ**
1. 全プロジェクトを棚卸しする
2. 各案件で「一番苦労したこと」を1行書く
3. 技術スタックをバージョン付きで整理する
4. 数字を入れられる箇所を探す
5. プロジェクト羅列をスキル軸で再編集する

SES経験5年以上の「業種横断視野」「環境適応力」「キャッチアップ速度」は、事業会社にとって即戦力として評価される要素だ。伝え方を変えるだけで、評価は変わる。

AI採用選別時代に入った今、動き出すタイミングは「今」以外にない。転職を決断しなくていい。まず職歴を棚卸しするところから始めてみてほしい。
