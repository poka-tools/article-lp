# Gemini API料金とGoogle検索グラウンディングの見方

## 公式URL

[Gemini Developer API pricing](https://ai.google.dev/gemini-api/docs/pricing)

## 何が分かるか

Google AI for Developersの料金ページでは、Gemini APIのFree、Paid、Enterpriseの違いと、モデル別のトークン単価が案内されています。Paidでは本番向けの高いレート制限、Context caching、Batch API、Googleの高度なモデルへのアクセスが示されています。

Gemini 3.1 Flash-Liteは高ボリューム処理向けとして、Paid Tierで入力100万トークンあたり0.25ドル、出力1.5ドルが案内されています。Gemini系では、Google SearchやMapsなどツール利用の料金も別に見る必要があります。

## 検索コストを見る理由

AIアプリで検索グラウンディングを使う場合、モデルのトークン料金だけでは総コストを判断できません。Google Searchによるグラウンディングは無料枠のあと、検索クエリやグラウンディング単位で課金される形が案内されています。

最新情報を扱うAIアプリでは、検索を毎回使うのか、必要なときだけ使うのか、検索結果をキャッシュするのかでコストが変わります。回答品質とコストのバランスを設計する力が必要です。

## 開発チームでの使い分け

Gemini APIを使う場合は、まず処理を分類します。大量の分類や翻訳はFlash-Lite、複雑な推論やコーディングは上位モデル、検索が必要な回答はグラウンディングあり、内部文書だけで答える場合は検索なしという分け方です。

Batch APIは大量処理のコスト削減に向いています。Context cachingは、長い前提情報を繰り返し使うアプリで効きます。検索、URL context、File Search、Code executionなどのツールも、要件に応じて使い分けましょう。

## 転職での見せ方

Gemini APIの経験を転職で語るなら、モデル名だけでなく、料金と品質のバランスをどう設計したかを説明しましょう。特に検索グラウンディングを使った経験は、情報の鮮度、根拠、コストの3点を合わせて話せると強いです。

「Gemini APIでAI機能を作成」ではなく、「検索が必要な質問だけグラウンディングを有効にし、通常回答はキャッシュと軽量モデルで処理した」と書くと、実務で使える設計力が伝わります。
