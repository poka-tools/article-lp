# CodexのChrome拡張・Goal mode正式化・Appshots──2026年5月の主要アップデート

OpenAI Codexに、2026年5月に複数の実用的なアップデートが入りました。個人開発から業務利用まで、実際に影響する変更点をまとめます。

## Chrome拡張機能のリリース

CodexがChromeブラウザの拡張機能として利用できるようになりました。

ブラウザから直接Codexにアクセスできるため、開発中に別ウィンドウへ切り替える手間が減ります。特にWebアプリ開発やドキュメント作業と並行してCodexを使う場面で、作業の流れが途切れにくくなります。

## Goal modeが正式機能に昇格

これまで試験的な機能だったGoal modeが、正式機能としてGA（一般提供）に移行しました。デスクトップアプリ・IDE拡張・CLIすべてで使えるようになっています。

Goal modeは、特定の目標を設定するとCodexが数時間から数日単位で自律的にタスクを進める機能です。長時間のバックグラウンド処理が現実的な選択肢になりました。

Goalsは専用ストレージに保存され、デフォルトで有効化されています。処理の途中でセッションが切れても進捗が保持される仕組みです。

## Appshots（macOS）

macOSで、両方のCommandキーを押すだけで最前面のアプリウィンドウをキャプチャしてCodexに渡せる機能が追加されました。

開発中に別ツールのエラー画面・デザインツールのUI・ドキュメントなどをそのままCodexに渡して質問できます。スクリーンショットを保存して貼り付けるという手順が不要になり、コンテキストの伝達が素早くできます。

## Codexモバイルプレビュー（iOS・Android）

ChatGPTモバイルアプリにCodexが統合され、iOS・Androidでプレビュー提供が始まりました。全プランが対象で、対応地域への展開が進んでいます。

外出中にCodexのGoal modeを起動して、戻ったときに作業が進んでいる──そういった使い方が実用的になってきています。

## ロック時のリモート操作（Locked computer use）

MacがロックされていてもCodex Mobileからリモートでデスクトップ操作を続けられるようになりました。

CI/CDのような長時間処理を別端末から確認・制御したい場面や、処理を走らせたまま離席するような使い方に対応します。

## ブラウザ操作の改善点

ブラウザ利用機能にも複数の改善が入りました。

- アドバンスアノテーションモード（注釈精度の向上）
- アセット抽出の高速化
- 読み取り専用のJavaScriptコンテキスト
- Chromeのタブグループ対応
- 操作の信頼性向上

Webスクレイピング・テスト自動化・ブラウザ操作が必要なタスクで、より安定した動作が期待できます。

## Permission profilesのAPI化

Permission profilesにリストAPIが追加され、継承・managed requirements.tomlのサポート・ランタイムでのリフレッシュ・Windowsサンドボックスとの統合強化が入りました。

チームでのCodex運用や、複数プロジェクトにまたがる権限管理をプログラム的に扱いやすくなります。

## GPT-5.3-CodexとNVIDIAインフラ

今回のアップデートと並行して、OpenAIはGPT-5.3-Codexをリリースしました。NVIDIAのGPUインフラとの組み合わせで処理速度と精度が向上しており、Goal modeのような長時間タスクの処理性能を底上げしています。

モデルの性能向上とツール側の機能拡充が同時に進んでいるため、数ヶ月前と比べてもCodexで扱えるタスクの規模と複雑さが大きく変わっています。

## Python SDKの認証サポート強化

Python SDKに第一級の認証サポートが追加されました。APIキーログイン・ChatGPTブラウザ認証・デバイスコードフローなど複数の認証方式が利用できるようになっています。

チームでのCodex活用やCIパイプラインへの組み込みを考える場合、認証の柔軟性が高まることでセットアップの選択肢が広がります。

## まとめ：実用フェーズへの移行

2026年5月のアップデート群が示しているのは、Codexが「コード補助ツール」から「自律的に動く開発エージェント」へ本格移行しているという事実です。

Goal modeのGA化・ロック時のリモート操作・モバイルとのシームレスな連携。これらを組み合わせることで、常時稼働する開発エージェントを実現する環境が整いつつあります。

転職市場でも「Codexを使ったことがある」ではなく「Goal modeを業務フローに組み込んだ」「ブラウザ操作の自動化をプロダクト開発に活用した」といった経験が、具体的な評価材料になっていきます。
